Qual è la Superficie di Minaccia nelle Pipeline CI/CD & nella Software Supply Chain?




L'integrazione e il rilascio continui (CI/CD) hanno trasformato la velocità del software aziendale. Tuttavia, i runner delle pipeline possiedono un livello di fiducia operativo eccezionale: accesso di produzione, chiavi cloud (AWS, GCP, Azure) e permessi di scrittura sui repository. In assenza di controlli rigorosi, le pipeline automatizzate diventano il vettore a più alto impatto per la compromissione della Software Supply Chain.


Il vettore più critico in GitHub Actions è l'uso scorretto del trigger pull_request_target. A differenza degli eventi pull_request standard, pull_request_target viene eseguito nel contesto privilegiato del repository di destinazione. Se combinato con il checkout di commit di fork non fidati (head.sha), aggressori esterni possono eseguire codice arbitrario sui runner ed esfiltrare secret di produzione.


La messa in sicurezza completa delle pipeline richiede tre controlli obbligatori: dichiarare il minimo privilegio in cima al workflow (permissions: contents: read), applicare il Pinning rigoroso di tutte le action di terze parti a commit SHA immutabili a 40 caratteri, e monitorare il traffico di rete in uscita per prevenire l'esfiltrazione automatizzata durante le build.
